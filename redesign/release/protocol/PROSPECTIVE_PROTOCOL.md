# PROSPECTIVE PROTOCOL — Claim-Specific Validation Study

**Frozen:** 2026-08-26 (commit recorded in FREEZE_RECORD.md)
**Status:** FROZEN BEFORE FINAL OUTCOME ACQUISITION
**Terminology discipline:** This is an internal prospective freeze. It is **not** a public preregistration; the word "preregistered" must not appear in any manuscript unless an OSF/registration deposit is actually created (see §11).

---

## 1. Research questions

RQ1. For each class of seed-matched claim (branches A–E), what evidence do existing simple strategies check, and what do they miss?
RQ2. Does the claim-specific framework improve invalid-claim detection without excessive false suppression, relative to simpler baselines?
RQ3. What are the measured costs (runtime, storage, configuration complexity) of each strategy?
RQ4. Do findings transfer between an open game environment and an open Monte Carlo physics simulator?

## 2. Design summary

- **Systems (frozen):** RLCard limit-holdem v1.2.0 (MIT; corrected from an erroneous Apache-2.0 label after freeze, D007); ising-monte-carlo-toolkit v0.1.0 sdist sha256 `caf24a50…aa` (MIT). Details: SYSTEM_MANIFEST.json.
- **Scenarios (frozen):** S0–S10 with construction-known ground-truth labels; mechanics in FAILURE_INJECTION_MANIFEST.json.
- **Methods (frozen):** B0 schedule-only; B1 outcome A/A; B2 trace A/A; B3 within-seed replication; B4 unpaired; B5 clustered/hierarchical; B6 event-keyed white-box; B7 full CSVF framework.
- **Sample size (frozen):** N=40 final seeds per system per scenario; 12 pilot seeds for timing/schema only (disjoint banks, derivation in SEED_MANIFEST.json).
- **Primary metrics (frozen):** M1 invalid-claim detection; M2 false-suppression (definitions + success criteria in METRICS_PREDECLARED.md). All other metrics secondary/exploratory.
- **Multiplicity:** Holm within primary family {M1,M2} across method contrasts; secondaries exploratory.

## 3. Execution plan

1. Pilot run on both systems with pilot seeds: verifies schemas, paths, timing only. Pilot outcome rows may NOT be read for analysis and may not alter thresholds/methods.
2. Freeze commit pushed to GitHub before any final-seed execution.
3. Final runs: full grid = {holdem, ising} × {S0..S10} × 40 seeds × methods scoring. Raw rows → redesign/results/final/raw/*.jsonl (level='decision' and level='outcome_pair' records only).
4. Crash policy: reruns permitted for infrastructure crashes only; every rerun logged to results/crash_log.txt (result-excluded).

## 4. Exclusions (frozen)

No data-driven exclusions. Cells failing schema validation are quarantined and reported as missingness, never imputed or silently dropped.

## 5. Analysis units

- Decision metrics: one cell = (system × scenario × seed × method × branch).
- Statistical-validity metrics (M4–M7): constructed replicate = one resampled evaluation from stored outcome pairs; unit declared per metric in METRICS_PREDECLARED.md.
- Pseudoreplication guard: decisions/sweeps/hands within one seed-condition are never counted as independent replicates.

## 6. Estimands & uncertainty

As predeclared in METRICS_PREDECLARED.md (Wilson/Clopper–Pearson for proportions; delta-method CI on log variance-ratio; binomial MCSE for Type-I/power estimates). Intervals called "confidence intervals" only where the repeated-sampling interpretation holds under the stated design; otherwise "uncertainty intervals" with construction described.

## 7. Stopping rules & budgets

Single-pass execution; no interim analysis; no threshold tuning. Total compute budget ≤ 3 CPU-hours on the development laptop; if exceeded, the campaign halts and reports partial coverage rather than extending silently.

## 8. Reporting consequences (predeclared)

- If M1≥0.95 ∧ M2≤0.10 for B7 AND no simpler baseline jointly dominates (M1, M2, M9): headline conclusion = claim-specific gating adds detection value at acceptable cost.
- If a simpler baseline dominates jointly: headline reports that result prominently; framework recommended only where its marginal detection is demonstrably needed.
- Cross-system disagreement (M13) reported as boundary conditions in Abstract if present.
- Equivalence claims require prespecified margins (none set ⇒ no equivalence language anywhere).
- Nonsignificant results never phrased as "no effect."
